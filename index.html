For Practitioners

For CX practitioners, or anyone interested in Context Engineering approaches to product, our academy is structured into three components:

  • Protogen Academy - learn the basics, and get comfortable with the concepts
  • DIY Projects - put the academy concepts to work in building three apps for yourself in a safe environment
  • Immersion Training - work as part of a broader team and collaborate on product development in a simulated client environment

All three of these sequential training environments have been carefully designed to set you up to be an AI Native powerhouse in real client environments.

Tools & Setup

If you prefer visual learning, watch this step here.

  1. Sign Up for GitHub 5:13

    Create a GitHub account using your work email (preferably Slalom email).

  2. Download Visual Studio Code 7:24

    Install Visual Studio Code (not Visual Studio) from the official website.

    Download Visual Studio Code

  3. Sign Up for Vercel 10:31

    Create a Vercel account and link it to your GitHub account. Choose the “Hobby” plan when prompted.

  4. Install Homebrew (Mac Only) 13:54

    Open Terminal (Applications > Utilities > Terminal), then run this command: 

    /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

    Enter your Mac password when prompted (no characters will show as you type).

  5. Install Git via Homebrew 15:55

    In Terminal, paste and run:

    brew install git

    If the command is not found, open a new Terminal window and try again.

  6. Open Visual Studio Code

    Launch Visual Studio Code.

  7. Create a New Project Folder 24:34

    In Visual Studio Code, click “Open” and create a new folder (for example, “my-homepage”).

  8. Install Copilot Extensions 25:56

    Go to Extensions (left sidebar), search for “Copilot”, and install both “Copilot” and “Copilot Chat”.

  9. Set Copilot Mode to Agent 27:15

    Switch Copilot mode from “Ask” to “Agent” for code editing.

  10. Generate Homepage Code 32:57

    In Copilot Agent, use this prompt and keep the generated files: 

    Create a simple HTML/CSS homepage with a blue gradient background, a hello world intro, a photo cropped in a circle, and a contact me button.

  11. Preview Your Homepage 33:37

    Right-click index.html and open it in your browser to view the homepage.

  12. Publish to GitHub 38:29

    Click the Source Control button in Visual Studio Code, select “Publish to GitHub”, and choose “Public” or “Private” as needed.

  13. Deploy to Vercel 41:43

    Go to Vercel.com, click “Add New Project”, import your GitHub repository, and deploy to get a public URL.

  14. Update and Sync Changes 48:12

    When you make changes (for example, adding a photo), commit and sync in Visual Studio Code. Vercel will automatically update your site with each GitHub push.

Build a Website

If you prefer visual learning, watch this step here.

  1. Start with your basic HTML/CSS website

  2. Choose a weather widget approach

    Decide to add a weather widget using a free API such as Open-Meteo or WeatherWidget.io.

  3. Generate an implementation brief

    Ask an AI assistant or chatbot for a technical brief and step-by-step implementation plan for integrating the widget.

  4. Document the plan in markdown

    Copy the provided technical brief and code into a new markdown (.md) file in your code editor.

  5. Implement in your editor

    Use your code editor (for example, Visual Studio Code) to execute the plan step by step:

    • Add required HTML elements for the widget.
    • Style the widget with CSS to match your site.
    • Add JavaScript to fetch and display weather data with the selected free API.
    • Optionally configure the widget to use the user's location for local weather.

  6. Review each step before moving on

    Confirm completion of each implementation step before continuing.

  7. Verify in browser

    Open your updated index.html file in a browser to confirm the weather widget appears and works.

  8. Deploy updates when ready

    If deploying, push your changes to your hosting platform (for example, Vercel).

  9. Troubleshoot as needed

    If issues appear, check code changes, adjust styles, or re-run the implementation steps.

  10. Customize the widget 15:14

    Optionally customize temperature units and appearance by updating the code or refining your prompts to the AI assistant.

Model Context

  1. Push to GitHub early and often 4:24

  2. Choose the right model for the task 3:47

    Match model strengths and limitations to what you’re trying to accomplish.

  3. Understand stateless model behavior 10:34

    Models retain context only in the active chat unless you explicitly re-provide it.

  4. Use short-term memory intentionally 14:25

    The chat window supports immediate interactions, but context can decay as threads grow.

  5. Build long-term memory in your repo 15:53

    Store key requirements, project notes, and design docs in markdown files and reference them in prompts.

  6. Start each chat with context 29:21

    Provide requirements, design system guidance, and technical constraints up front.

  7. Use markdown across agents 37:26

    Transfer structured information between agents and preserve editable records of project decisions.

  8. Ask for specs and layered tasks 53:03

    Prompt for both high-level and granular task breakdowns to organize implementation clearly.

  9. Keep markdown artifacts current 52:04

    Download and edit markdown documents as project details evolve to keep outputs consistent.

  10. Guide execution with checklists 54:12

    Use task lists to drive AI through sequential execution while preserving context and momentum.

Planning Your Product

If you prefer visual learning, watch this step here.

  1. Define the outcome first 2:18

    Clarify the user problem, the audience, and what success looks like before writing implementation prompts.

  2. Set measurable success criteria 6:42

    Establish concrete metrics such as task completion rate, conversion lift, or reduced manual effort.

  3. Choose the smallest viable scope 11:07

    Prioritize a focused MVP that can be shipped quickly and validated with real users.

  4. Map core user journeys 15:36

    Identify primary and secondary flows so your prompts and build tasks reflect actual customer behavior.

  5. Break work into priorities 20:14

    Group tasks into now, next, and later to keep progress steady and avoid overbuilding too early.

  6. Write a concise product brief 25:48

    Capture goals, constraints, and assumptions in markdown so every contributor starts from shared context.

  7. Align on technical guardrails 31:22

    Decide platform choices, architecture boundaries, and non-functional requirements up front.

  8. Plan risks and unknowns 37:05

    List assumptions to test first so uncertainty is reduced early in the project lifecycle.

  9. Turn plans into implementation tasks 43:19

    Convert high-level intent into a clear sequence that AI and humans can execute reliably.

  10. Review and commit the plan 49:44

    Save the final planning artifacts in your repository before moving into active build mode.

Mobilizing Your Plan Into Action

If you prefer visual learning, watch this step here.

  1. Start from a single source of truth 3:04

    Use your planning markdown as the authoritative reference for scope, priorities, and acceptance criteria.

  2. Create a visible execution board 7:26

    Track tasks by status so the team and AI agents can coordinate around the same priorities.

  3. Ship an end-to-end thin slice first 12:15

    Deliver one complete user flow early to validate architecture, tooling, and user value.

  4. Keep prompts task-specific 17:03

    Ask for targeted outputs per task instead of broad, mixed prompts to improve consistency.

  5. Commit code in small increments 22:41

    Push frequently so progress is recoverable and easier to review, debug, and iterate.

  6. Validate after every meaningful change 28:08

    Run checks continuously to catch regressions before they compound across features.

  7. Capture blockers immediately 34:27

    Document constraints and unknowns in context files to preserve momentum across sessions.

  8. Demo progress in short cycles 40:12

    Share frequent working increments to tighten feedback loops and reduce late-stage rework.

  9. Refine scope using evidence 46:33

    Promote, defer, or remove tasks based on real outcomes and stakeholder feedback.

  10. Prepare handoff-ready artifacts 52:09

    Keep implementation notes, decisions, and next actions current for seamless team collaboration.
